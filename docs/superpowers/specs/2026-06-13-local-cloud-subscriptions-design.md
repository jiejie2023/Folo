# Local and Cloud Subscriptions Design

## 背景

Folo 现在的订阅模型以云端为主：

- 启动时先从本地 `follow.db` 缓存恢复数据。
- 订阅栏挂载后会调用云端 `/subscriptions`。
- 登录后云端订阅会以 `resetBeforeUpsert: true` 的方式覆盖当前订阅列表。
- 添加订阅走 `api().subscriptions.create(...)`，成功后再写入本地缓存。

这意味着当前本地数据库主要是缓存，不是完整的本地 RSS 管理层。

我们要把本地 RSS 变成一等能力，同时保留登录账号的同步价值。

## 产品原则

账号不是主资料库，而是跨设备同步容器。

本地订阅是默认路径：

- 默认添加 RSS 到本地。
- 本地订阅只存在当前电脑。
- 本地订阅不占账号订阅额度。
- 本地订阅可以手动同步到账号。

云端订阅是精选同步路径：

- 用户常看的、需要在手机或其他电脑同步的源，可以放进账号。
- 云端订阅继续遵守 Folo 官方账号限制。
- 云端订阅仍由官方 API 管理。

## 第一版目标

第一版只做 feed 订阅，不做 list、inbox、社交账号等复杂对象的本地化。

目标能力：

- 登录后同时保留云端订阅和本地订阅。
- 左侧订阅栏按来源分区管理：

```text
账号同步
  AI
    OpenAI News

本地订阅
  AI
    Ahead of AI
  Developer
    GitHub Blog
```

- 阅读时间线可以合并显示账号订阅和本地订阅。
- 添加 RSS/RSSHub 默认进入本地订阅。
- 本地订阅可以手动同步到账号。
- 云端订阅可以复制为本地订阅。
- 用户能一眼分清订阅来源。

## 非目标

第一版不做这些事：

- 不自建 Folo 后端。
- 不绕过云端账号限制同步到官方账号。
- 不实现多设备同步本地订阅。
- 不把 list/inbox 迁移成本地管理对象。
- 不直接手动编辑 IndexedDB 或 `follow.db`。
- 不承诺离线抓取所有 RSS 内容。

## 数据模型

订阅需要有来源字段。

建议字段：

```ts
source: "cloud" | "local"
```

含义：

- `cloud`：来自 Folo 账号同步。
- `local`：当前设备本地订阅。

由于现有 `subscriptions` 表没有来源字段，第一版直接在 `subscriptions` 表新增来源列。暂不使用伴随表，因为查询和 UI 判断需要直接读取来源。

建议默认值：

```text
cloud
```

原因：

- 兼容现有数据库。
- 旧数据没有来源时按云端缓存处理。
- 后续本地添加时明确写入 `local`。

## 同步规则

当前登录后的云端拉取逻辑会清空订阅表再写入云端数据。

新规则：

```text
拉取云端订阅
  -> 只替换 source = cloud 的订阅
  -> 保留 source = local 的订阅
  -> UI 合并两类订阅
```

这避免登录后本地订阅消失。

## 添加订阅规则

默认添加到本地：

```text
用户输入 RSS/RSSHub URL
  -> 调用现有 feed 预览接口解析 feed
  -> 写入本地 feeds 表
  -> 写入本地 subscriptions 表，source = local
```

同步到账号：

```text
用户右键本地订阅
  -> 点击“同步到账号”
  -> 调用 api().subscriptions.create(...)
  -> 成功后把该订阅从 local 标记为 cloud
```

第一版不保留本地副本，避免同一个源在两个分区重复出现。

复制为本地：

```text
用户右键云端订阅
  -> 点击“复制为本地订阅”
  -> 复用 feed 数据
  -> 新建 source = local 的订阅
```

如果同一个 feed 已经有本地订阅，提示已经存在。

## 阅读时间线

订阅栏管理分区，时间线阅读合并。

阅读逻辑：

- 左侧“全部”时间线包含 `cloud + local`。
- 单个分区下点击源时，只看该源。
- 本地源的文章优先从本地 entry store 读取。
- 如果本地没有文章，第一版可以继续通过现有 feed 预览能力获取近期 entries 并写入本地缓存。

第一版允许本地源文章刷新能力较弱，但不能出现“左侧有源，右侧永远空白且没有提示”的体验。

## UI 设计

订阅栏：

- 顶层分为“账号同步”和“本地订阅”。
- 各分区内部继续按现有分类展示。
- 本地订阅旁边显示简短标记，例如“本地”。
- 云端订阅旁边显示简短标记，例如“同步”。

右键菜单：

- 本地订阅：
  - 同步到账号
  - 编辑分类
  - 取消本地订阅
- 云端订阅：
  - 复制为本地订阅
  - 编辑分类
  - 取消云端订阅

发现页/添加页：

- 提交按钮文案改为“添加到本地”。
- 登录状态下可额外显示“同步到账号”操作。
- 未登录状态下仍允许“添加到本地”。

## 错误处理

添加本地订阅失败：

- 显示解析失败或写入失败。
- 不创建半成品订阅。

同步到账号失败：

- 保留本地订阅。
- 显示云端同步失败原因。

重复订阅：

- 本地已有同 URL 或同 feedId 时，不重复添加。
- 云端已有同 feedId 时，同步到账号时提示已在账号中。

云端刷新失败：

- 不删除本地订阅。
- 保留上一次云端订阅缓存。

## 测试策略

优先覆盖纯逻辑，不先碰 UI 大测试。

需要测试：

- 云端 fetch 只替换 cloud 订阅，不删除 local 订阅。
- 本地订阅 upsert 会写入 `source = local`。
- 订阅选择器能按 source 分组。
- 同一个 feedId 不会被本地重复添加。
- 云端同步失败不会删除本地订阅。

UI 测试放在第一版逻辑稳定后再补。

## 实施顺序

1. 给订阅模型增加 source 概念。
2. 修改云端同步逻辑，只重置 cloud 订阅。
3. 增加本地订阅 service/action。
4. 修改 FeedForm：未登录也能添加到本地，登录后默认也是本地。
5. 修改订阅栏分组显示。
6. 增加“同步到账号”和“复制为本地订阅”的右键操作。
7. 验证本地源在时间线中能显示近期文章或合理提示。

## 成功标准

- 登录账号后，本地订阅不会消失。
- 添加新 RSS 默认进入“本地订阅”分区。
- 用户可以把本地订阅同步到账号。
- 用户可以清楚区分本地订阅和账号同步订阅。
- 账号订阅限制只影响同步到账号的订阅，不影响本地订阅。
